# Visual MVP Design — Taskbar Inn

この文書は、`taskbar inn` のビジュアル実装に入る前の設計メモです。参考画像 `docs/references/visual_concept_taskbar_inn_godot.png` は、完成素材として直接使わず、暖色系の中世ファンタジー宿屋、木枠と羊皮紙風 UI、背景・キャラ・吹き出し・ライト・UI を別レイヤーとして扱う方針の参照にします。

Godot 実装では、既存方針どおり `.tscn` を増やしすぎず、必要なノードは主に `.gd` から生成します。この設計書は Godot 初学者でも後から実装順を追えるように、必要アセット、ノード構成、作業順を具体化します。

## 1. 目的とスコープ

### 目的

Visual MVP の目的は、宿屋経営ロジックに「小さな宿で人が生活している感じ」を足すことです。最初から豪華な完成アートを量産するのではなく、宿屋の1部屋、店員1人、客2人、簡素な歩行・座り・寝る状態、吹き出し、ランプの揺らぎが動く状態を作ります。

特に優先するのは次の2つです。

- 背景画像: 宿屋の室内を固定ビューで見せる土台
- キャラクタースプライト: 店員と客が小さく動き、生活感を出す土台

### 今回やること

- Visual MVP に必要な背景・キャラ・演出・UIアセットを洗い出す
- Godot でのノード構成を、初心者向けに整理する
- 背景レベルアップを最終8段階へ拡張しやすい方針にする
- 生成AIで素材を作る場合の順番と注意点を決める
- 会話吹き出しを将来のイベントフックにしやすい構成にする

### 今回やらないこと

- 家具・調度品・アイテム類の本格実装
- 全8段階の宿背景を最初から完成させること
- 座る、寝る、食事、会話のフルアニメ化
- 複雑なカットイン、戦闘、探索画面、マップ移動
- 参考画像を切り抜いてそのままゲーム素材にすること

家具や小物は将来的に追加します。ただし MVP 時点では背景の中に描き込むか、空の拡張レイヤーを用意する程度に留めます。

### MVP の到達目標

MVP では以下が見えれば十分です。

- 宿屋の1部屋背景が表示される
- 店員1人、客2人程度が表示される
- 客が短い距離を歩く
- 客がテーブル席に移動し、座り状態へ切り替わる
- 客がベッド付近に移動し、寝る状態へ切り替わる
- 感情アイコンや短いテキスト吹き出しが出る
- ランプの炎や暖かい光が少し揺らぐ
- 背景を宿Lvに応じて差し替えられる入口がある

## 2. 必要アセット一覧

推奨ディレクトリは、後で Godot の `res://assets/...` として読みやすい構成にします。現時点でディレクトリが未作成でも、設計上は以下を基準にします。

```text
assets/
  visual/
    backgrounds/
      inn_room/
    characters/
      staff/
      guests/
    fx/
      lights/
    ui/
      bubbles/
      panels/
```

### 背景アセット

背景は、最初から細かい家具ごとに分解しすぎると制作量が膨らみます。MVP では「1枚絵ベース + 最小限の演出レイヤー」が現実的です。将来、宿Lvや家具追加に対応するため、構造だけはレイヤー分割を前提にします。

| アセット | ファイル名例 | 役割 | MVP |
|---|---|---|---|
| 宿Lv1 背景統合絵 | `assets/visual/backgrounds/inn_room/inn_room_lv01_base.png` | 小さな素泊まり宿の室内。床・壁・基本家具は描き込みで可 | 必須 |
| 背景マスク/歩行範囲メモ | `assets/visual/backgrounds/inn_room/inn_room_lv01_walk_map.png` | 実装者が歩ける範囲を把握するための参照。ゲーム内表示は不要 | 推奨 |
| ランプ発光レイヤー | `assets/visual/fx/lights/lamp_glow_lv01.png` | ランプ周辺の暖色光を加算表示する | 必須 |
| 窓明かり/暖炉光レイヤー | `assets/visual/fx/lights/window_warm_glow_lv01.png` | 室内の暖かみを足す。透明PNG | 後回し可 |
| 宿Lv中盤 背景 | `assets/visual/backgrounds/inn_room/inn_room_lv04_base.png` | 家具や部屋が少し豪華な代表差分 | 後回し可 |
| 宿Lv終盤 背景 | `assets/visual/backgrounds/inn_room/inn_room_lv08_base.png` | 最終到達イメージの代表差分 | 後回し可 |

MVP では `inn_room_lv01_base.png` をまず1枚作ります。レイヤー分割は、最低限 `base` と `glow` の2層で開始します。床、壁、ベッド、テーブルなどは背景に描き込んで構いません。家具を個別に動かす必要が出た時だけ、後から `props` レイヤーを追加します。

将来の背景分割は次の順番が扱いやすいです。

| レイヤー | 内容 | Godot ノード |
|---|---|---|
| `base` | 床・壁・大きな家具まで含む背景 | `Sprite2D` |
| `walk_guides` | 座席、ベッド、入口などの位置データ。画像ではなく座標定義でも可 | `Node2D` |
| `props_back` | キャラの背後に来る大物 | `Sprite2D` |
| `characters` | 店員・客 | `Node2D` 配下 |
| `props_front` | キャラの手前に来る柱や手すり | `Sprite2D` |
| `lights` | ランプ、窓、暖炉の発光 | `Sprite2D` / `Light2D` |
| `ui` | パネル、吹き出し、ボタン | `Control` |

### キャラクターアセット

キャラクターは小さめで、モーション数を抑えます。歩行を最優先にし、座る・寝るはフルアニメではなく状態切替で表現します。

| アセット | ファイル名例 | 役割 | MVP |
|---|---|---|---|
| 店員 歩行 | `assets/visual/characters/staff/staff_owner_walk.png` | 店員の左右/上下または左右のみ歩行スプライトシート | 必須 |
| 店員 待機 | `assets/visual/characters/staff/staff_owner_idle.png` | 立ち待機。歩行の1フレーム流用でも可 | 必須 |
| 客A 歩行 | `assets/visual/characters/guests/guest_traveler_walk.png` | 旅人系の歩行 | 必須 |
| 客A 待機 | `assets/visual/characters/guests/guest_traveler_idle.png` | 立ち待機 | 必須 |
| 客A 座り | `assets/visual/characters/guests/guest_traveler_sit.png` | 椅子に座った状態。1枚絵で可 | 必須 |
| 客A 寝る | `assets/visual/characters/guests/guest_traveler_sleep.png` | ベッド付近で寝ている状態。1枚絵で可 | 必須 |
| 客B 歩行/状態 | `assets/visual/characters/guests/guest_merchant_walk.png` など | 2人目の見た目差分 | 後回し可 |
| 表情差分 | `assets/visual/characters/guests/guest_traveler_faces.png` | 会話用の顔だけ差分 | 後回し可 |

MVP の最低種類数は、店員1種類、客1種類で開始して問題ありません。ただし画面上では客2人を同じスプライトの色違いで出せると、生活感が出しやすくなります。可能なら客は「旅人」と「商人」の2種類を早めに用意します。

歩行スプライトは、まず左右歩行だけで十分です。奥行き表現が必要なら、上下歩行は後で足します。

推奨フレーム構成:

| 状態 | 推奨フレーム数 | 説明 |
|---|---:|---|
| `idle` | 1〜2 | 呼吸程度。最初は1枚で可 |
| `walk_side` | 4 | 左右移動用。反転で左右を兼用 |
| `walk_down` | 4 | 画面手前方向。MVPでは省略可 |
| `walk_up` | 4 | 画面奥方向。MVPでは省略可 |
| `sit` | 1 | テーブル席で座っている状態 |
| `sleep` | 1〜2 | 就寝状態。Zzz演出は吹き出し側で表現 |

### 最小限の演出アセット

| アセット | ファイル名例 | 役割 | MVP |
|---|---|---|---|
| ランプ炎 | `assets/visual/fx/lights/lamp_flame_sheet.png` | 2〜4フレームの小さな炎 | 必須 |
| ランプ光 | `assets/visual/fx/lights/lamp_glow.png` | 透明PNG。拡大縮小と透明度変化で揺らぐ | 必須 |
| Zzz アイコン | `assets/visual/ui/bubbles/icon_sleep.png` | 寝ている客の上に出す | 推奨 |
| 満足アイコン | `assets/visual/ui/bubbles/icon_happy.png` | 満足状態 | 必須 |
| 不満アイコン | `assets/visual/ui/bubbles/icon_unhappy.png` | 汚れや食事不足などの軽い警告 | 必須 |

ランプの揺らぎは、`AnimatedSprite2D` で炎を切り替えるか、`Sprite2D` の `modulate.a` と `scale` を `Tween` で少し変えるだけでも成立します。見た目のコストに対して効果が大きいので、MVP に入れる価値があります。

### UI/吹き出し系の最小アセット

| アセット | ファイル名例 | 役割 | MVP |
|---|---|---|---|
| 感情吹き出し枠 | `assets/visual/ui/bubbles/emotion_bubble_9slice.png` | アイコン用の小さな吹き出し | 必須 |
| 会話吹き出し枠 | `assets/visual/ui/bubbles/speech_bubble_9slice.png` | 短い台詞表示 | 必須 |
| 羊皮紙パネル | `assets/visual/ui/panels/parchment_panel_9slice.png` | expanded UI 用の背景パネル | 後回し可 |
| 木枠パネル | `assets/visual/ui/panels/wood_frame_9slice.png` | 参考画像の木枠UI方向 | 後回し可 |

吹き出しは `NinePatchRect` を使うと、短い台詞と少し長い台詞の両方に対応しやすくなります。MVP では画像がまだ無くても、`PanelContainer` と `Label` で仮実装して問題ありません。

## 3. Godotノード構成

Visual MVP は、既存の `main.tscn` を増やさず、`main.gd` から `InnVisualView` のような表示用ノードを生成する方針が合います。将来ファイルを追加するなら、候補は `scripts/ui/inn_visual_view.gd` です。

### Scene Tree 例

```text
Main (Node)
  WindowManager
  CompactView (Control)
  ExpandedView (Control)
  InnVisualView (Node2D)
    BackgroundLayer (Node2D)
      InnRoomBase (Sprite2D)
      BackProps (Node2D)
    MarkerLayer (Node2D)
      SeatMarker_01 (Marker2D)
      SeatMarker_02 (Marker2D)
      BedMarker_01 (Marker2D)
      EntranceMarker (Marker2D)
    CharacterLayer (Node2D)
      StaffOwner (Node2D)
        Body (AnimatedSprite2D)
        BubbleAnchor (Marker2D)
      Guest_01 (Node2D)
        Body (AnimatedSprite2D)
        BubbleAnchor (Marker2D)
      Guest_02 (Node2D)
        Body (AnimatedSprite2D)
        BubbleAnchor (Marker2D)
    FrontLayer (Node2D)
      FrontProps (Sprite2D)
    LightLayer (Node2D)
      LampFlame (AnimatedSprite2D)
      LampGlow (Sprite2D)
    BubbleLayer (Control)
      EmotionBubble (Control)
      SpeechBubble (Control)
    HudLayer (Control)
      MinimalStatusBar (Control)
```

既存の compact / expanded UI があるため、Visual MVP は最初から全画面UIを作り直さず、宿屋の生活感を見せる `InnVisualView` として足すのが安全です。compact view に小さく入れるか、expanded のホームページに大きめに置くかは実装時に選べます。

### 各ノードの役割

| ノード | 役割 |
|---|---|
| `InnVisualView` | 宿屋ビジュアル全体の親。表示/非表示やスケール調整をまとめる |
| `BackgroundLayer` | 背景1枚絵と、将来の背面小物を置く |
| `MarkerLayer` | 座席、ベッド、入口などの目的地座標を管理する |
| `CharacterLayer` | 店員と客を置く。Y座標順で前後関係を調整する |
| `FrontLayer` | 手前に被る柱、テーブル端、階段手すりなどを将来置く |
| `LightLayer` | ランプ、暖炉、窓明かりなどの発光表現 |
| `BubbleLayer` | 感情アイコンと会話吹き出しを置く。画面座標に変換して表示する |
| `HudLayer` | 最小限のステータスや操作ボタン。既存UIとの重複は避ける |

### Sprite2D / AnimatedSprite2D / Node2D / Control の使い分け

| 種類 | 使いどころ |
|---|---|
| `Node2D` | 2D空間上の親ノード。キャラ、背景レイヤー、目的地グループなど、位置を持つまとまり |
| `Sprite2D` | 1枚画像を置く。背景、光レイヤー、前景小物など |
| `AnimatedSprite2D` | フレームを切り替える画像。歩行、炎、簡単な待機モーションなど |
| `Control` | UI用。吹き出し、パネル、ボタン、ラベルなど |
| `Marker2D` | 座席やベッドなど、見えない位置目印 |
| `Light2D` | 本格的な2Dライト。MVPでは `Sprite2D` の光PNGでも可 |

背景やキャラはゲーム世界の座標に置くため `Node2D` 系、吹き出しやUIは画面上で読みやすく配置するため `Control` 系に分けます。

### 背景をどう置くか

MVP では `Sprite2D` に `inn_room_lv01_base.png` を表示します。画面サイズに合わせて `InnVisualView` 全体を縮小するか、背景画像を最初から表示サイズに合わせます。

固定ビューなので、カメラ移動は不要です。背景の中に「歩ける範囲」「座席位置」「ベッド位置」をあらかじめ決め、`Marker2D` または座標配列で管理します。

### キャラクターの歩行

キャラは `Node2D` を親にして、その下に `AnimatedSprite2D` を置きます。移動時は親の `position` を目的地へ `Tween` で動かし、移動中だけ `walk_side` を再生します。目的地に着いたら `idle`、`sit`、`sleep` へ切り替えます。

MVP の行動例:

```text
EntranceMarker → SeatMarker_01 → idle/sit → BedMarker_01 → sleep
```

移動経路は最初から本格的な経路探索にしなくて構いません。宿屋の1部屋だけなら、目的地同士を直線移動するだけで十分です。家具にめり込む場合だけ、中間点を1つ追加します。

### 座る・寝るの状態切替

座る、寝るはフルアニメにしません。目的地へ歩いたあと、`AnimatedSprite2D.animation` を `sit` または `sleep` に切り替えます。向きが合わない場合は、座席ごとに `flip_h` や少しの `rotation_degrees` を指定します。

寝る状態はキャラをベッド上に重ねるより、ベッド付近に寝姿スプライトを出す方が破綻しにくいです。背景にベッドが描き込まれている場合、寝姿が見える位置だけを `BedMarker` として調整します。

### 吹き出しの出し方

各キャラに `BubbleAnchor` を持たせ、吹き出しは `BubbleLayer` に作ります。表示時に、キャラの `BubbleAnchor` の2D座標を画面座標へ変換し、その少し上に `EmotionBubble` または `SpeechBubble` を表示します。

吹き出しは2種類に分けます。

| 種類 | 内容 | 例 |
|---|---|---|
| 感情吹き出し | アイコン中心。短時間で消える | 満足、不満、眠い、驚き |
| 会話吹き出し | 短文。イベントやヒントにも使う | 「今日は満室だね」「厨房が忙しそう」 |

将来、会話をイベントフックにする場合は、台詞データに `event_id` や `hint_key` を持たせます。MVP では見た目だけでも、データ構造は次のようにしておくと拡張しやすいです。

```text
line_id: guest_dirty_hint_01
speaker_type: traveler
text: "床が少し気になるな..."
hook: dirtiness_high
```

### ランプの揺らぎ

ランプは `AnimatedSprite2D` の炎と、透明な `Sprite2D` の光を重ねます。炎は2〜4フレームで十分です。光は `Tween` で透明度を 0.75〜1.0 の間でゆっくり変えると、暖かい揺らぎに見えます。

本格的な `Light2D` は後回しで構いません。MVP では「透明PNGの発光レイヤーを少し揺らす」ほうが簡単で、絵柄も安定します。

## 4. 実装順

### 1. 仮背景で画面を作る

作業内容: まずは灰色の矩形や仮画像で `InnVisualView` を作り、背景が表示される場所を決めます。compact に入れるか expanded のホームに入れるかもこの段階で試します。

完了条件:

- 宿屋背景の表示領域が決まっている
- 画面サイズ変更時に背景が崩れない
- 座席、ベッド、入口の仮座標が置かれている

詰まりやすいポイント:

- `Control` のUI座標と `Node2D` の世界座標を混ぜると位置がずれます
- まず背景とキャラは `Node2D`、吹き出しとボタンは `Control` と分けます

仮実装でよい部分:

- 背景画像は単色矩形や既存の参考用ラフでよい
- 座席やベッドは見えない座標だけでもよい

### 2. キャラ1体を歩かせる

作業内容: 客1人を入口から座席まで移動させます。移動中は歩行、到着後は待機に切り替えます。

完了条件:

- `Guest_01` が目的地まで移動する
- 移動中に歩行アニメが再生される
- 停止時に待機へ戻る

詰まりやすいポイント:

- スプライトシートのフレームサイズ設定
- 左右移動時の `flip_h`
- 目的地に着いた後も歩行アニメが止まらないこと

仮実装でよい部分:

- 歩行は4フレームで十分
- 方向は左右のみでよい

### 3. 客を座らせる

作業内容: 座席に到着した客のアニメーションを `sit` に切り替えます。

完了条件:

- 客が座席へ移動する
- 到着後、座り画像に切り替わる
- 座った位置が背景のテーブルや椅子と大きくずれない

詰まりやすいポイント:

- 背景に椅子が描き込まれている場合、座りスプライトの位置合わせが難しい
- キャラがテーブルの前後どちらに見えるべきか迷いやすい

仮実装でよい部分:

- 最初は椅子を背景に描き込まず、座標だけで確認してよい
- 前後関係は後で `FrontLayer` を足して調整する

### 4. 寝る状態差分を出す

作業内容: 客がベッド付近へ移動し、寝る状態画像へ切り替わります。必要なら `Zzz` アイコンを出します。

完了条件:

- 客がベッド位置へ移動する
- 到着後、寝る画像に切り替わる
- 就寝中であることが一目で分かる

詰まりやすいポイント:

- ベッドにキャラを自然に重ねるのは難しいため、最初は少し手前に置く
- 寝る向きは1方向だけに固定する

仮実装でよい部分:

- 寝る画像は1枚でよい
- `Zzz` はテキストラベルでもよい

### 5. 吹き出しを出す

作業内容: 客の頭上に感情アイコンと短い会話を表示します。生活感と、将来のイベントヒントの土台になります。

完了条件:

- 感情吹き出しがキャラの上に出る
- 一定時間で消える
- 短いテキスト吹き出しも出せる

詰まりやすいポイント:

- キャラの `Node2D` 座標を `Control` の表示位置へ変換する必要があります
- 長文を入れると画面を圧迫するため、台詞は短くします

仮実装でよい部分:

- 吹き出し画像が無くても `PanelContainer + Label` でよい
- 感情アイコンは記号や仮アイコンでよい

### 6. ランプの揺らぎを追加する

作業内容: ランプ炎と光レイヤーを追加し、炎のアニメまたは光の透明度変化を入れます。

完了条件:

- ランプ付近が暖かく見える
- 光がわずかに揺らいでいる
- 画面全体が眩しくなりすぎない

詰まりやすいポイント:

- 発光レイヤーが濃すぎるとUIやキャラが読みにくくなります
- `Light2D` より透明PNGのほうが絵柄を制御しやすいです

仮実装でよい部分:

- 炎アニメは2フレームでもよい
- 光は `Tween` だけでよい

### 7. 背景差分（宿Lv）を検証する

作業内容: 宿Lvに応じて背景画像を差し替えられるようにします。MVP では Lv1 だけ完成、Lv4 や Lv8 はラフ画像でも構いません。

完了条件:

- `service_rank` または宿Lvに応じて背景パスを選べる
- 背景を差し替えてもキャラ座標が大きく破綻しない
- 将来の8段階化に必要な命名規則が決まっている

詰まりやすいポイント:

- 背景ごとにテーブルやベッドの位置が変わると、キャラの目的地も全部調整が必要になります
- 最初は「部屋の基本構図を固定し、豪華さだけ変える」ほうが量産しやすいです

仮実装でよい部分:

- Lv4/Lv8 はラフや色違いでよい
- 実際のゲーム内反映は後回しでも、差し替え関数だけ作っておくとよい

## 5. 背景レベルアップ方針

宿屋は最終的に Lv1〜Lv8 まで豪華になります。ただし、最初から8枚すべてを作るべきではありません。ゲームロジック、UIサイズ、キャラ移動、座標管理が固まる前に大量制作すると、後で全素材の修正が発生しやすいからです。

### MVP 時点のおすすめ

MVP では、まず Lv1 の完成度を上げます。次に代表差分として Lv4 と Lv8 のラフを作り、「この構図で本当に8段階に展開できるか」を確認します。

推奨順:

1. `Lv1`: 小さな素泊まり宿。質素だが暖かい
2. `Lv4`: 取引宿/中規模化。客席や装飾が増える
3. `Lv8`: 大規模ホテル級。照明、階層、豪華な内装が増える
4. 問題なければ Lv2/3/5/6/7 を補完する

### 背景1枚差し替え方式

| 観点 | 内容 |
|---|---|
| メリット | 作る画像が分かりやすい。Godot実装も `Sprite2D.texture` 差し替えだけで済む |
| デメリット | 家具や光だけを個別に変えにくい。差分が増えるほど修正が重くなる |
| 向いている段階 | MVP、固定ビュー、背景美術の方向確認 |

MVP ではこの方式が最も安全です。背景内に家具を描き込んでしまってよいので、まず画面の印象を作ります。

### 差分レイヤー方式

| 観点 | 内容 |
|---|---|
| メリット | 家具、装飾、光、前景を個別に足せる。宿Lvごとの差分が管理しやすい |
| デメリット | 素材数と座標調整が増える。初期実装が複雑になる |
| 向いている段階 | Lv差分が増えた後、家具や展示物を追加する段階 |

将来は `base + props + lights + front` の分割へ進めます。ただし MVP では `base + lights` 程度で止め、家具・小物の個別PNG化は後回しにします。

### 量産しやすい方針

8段階を作る前提では、背景の構図を固定することが重要です。入口、テーブル、ベッド、店員の立ち位置、客の歩行エリアはできるだけ変えず、壁材、照明、布、装飾、奥行き、客席数で豪華さを表現します。

宿Lvごとの方向性:

| Lv | 背景の見た目 |
|---:|---|
| 1 | 小さな素泊まり宿。木床、簡素なベッド、暖かいランプ |
| 2 | 食事つき宿。小さな厨房感や食卓の存在感 |
| 3 | 畑つき宿。窓辺の緑や保存食の雰囲気 |
| 4 | 取引宿。荷物棚、商人向けの落ち着き |
| 5 | 名物宿。装飾、看板、評判のある店らしさ |
| 6 | 温泉宿。湯気や柔らかい光、和みの演出 |
| 7 | リゾート宿。庭園感、酒場感、VIP向けの照明 |
| 8 | 大規模ホテル。多層構造、豪華な照明、広い客席 |

## 6. 生成AI活用方針

生成AIは、いきなり量産に使うより、先に「統一された完成イメージ」を作るほうが破綻しにくいです。特に背景とキャラの絵柄差が出やすいため、最初に基準絵を決めます。

### 推奨順

1. 完成イメージの1枚絵を作る
2. その絵柄を基準に、背景Lv1を単体で作る
3. 背景からキャラを除いたクリーン版を作る
4. 店員キャラの正面/横/背面/小サイズを作る
5. 客キャラ1種類の歩行・座り・寝る差分を作る
6. ランプ光、炎、吹き出しなど小さな演出素材を作る
7. Lv4/Lv8 の背景ラフを作って、8段階化できるか確認する

### 完成イメージを先に作る理由

完成イメージは、色、線、明るさ、キャラの頭身、UIの質感を揃える基準になります。ただし、それをゲーム素材として直接使うのではなく、背景・キャラ・UI・ライトへ分解するための「アートターゲット」として使います。

今回の参考画像もこの扱いです。暖色の木造宿、羊皮紙UI、木枠、ランプの発光、小さなキャラ、レイヤー分解の考え方を読み取り、実素材は別途ゲーム用に作ります。

### 背景を単体で作る

ゲーム背景には、キャラやUIが重なります。背景生成時は「人がいない室内」「中央や通路にキャラを置ける空間」「テーブルとベッドの位置が読み取れる構図」を指定します。

避けたいもの:

- 画面全体に小物が多すぎてキャラが見えない
- 入口、座席、ベッドの位置が曖昧
- 強い逆光でキャラやUIが読みにくい
- レベル差分ごとに部屋の構図が大きく変わる

### キャラを個別に作る

キャラは背景とは別に、透明背景のスプライトとして作ります。小さく表示するため、細かい装飾よりシルエットと色分けが重要です。

最初に作るキャラ:

- 店員: オーナー/宿の人。常に画面にいて宿の顔になる
- 客A: 旅人。最初の汎用客
- 客B: 商人または冒険者。見た目差分用

座る・寝るは、歩行スプライトから派生させます。フルアニメを作らず、1枚差分で状態が伝われば十分です。

### 統一感を保つ注意点

- 背景とキャラの光源方向を揃える
- キャラの輪郭線の太さを揃える
- 彩度を上げすぎず、暖かい茶・金・赤を基調にする
- UIは羊皮紙と木枠に寄せるが、文字の読みやすさを優先する
- 背景は細密、キャラは小さく読みやすく、UIはコントラスト高めにする

### 最初に作るべき素材の優先順位

| 優先 | 素材 | 理由 |
|---:|---|---|
| 1 | Lv1 背景クリーン版 | 画面の印象と座標設計の土台 |
| 2 | 店員 idle/walk | 宿に人がいる感じの核 |
| 3 | 客A walk/sit/sleep | MVPの行動確認に必要 |
| 4 | ランプ炎/光 | 少ない工数で暖かさが出る |
| 5 | 感情/会話吹き出し | 生活感とイベントヒントの土台 |
| 6 | 客B 差分 | 同じ客ばかりに見える問題を軽減 |
| 7 | Lv4/Lv8 背景ラフ | レベルアップ表現の検証 |

## 7. 最後に要約

今回のMVPでやるべき最小構成は、Lv1宿屋背景1枚、店員1人、客1〜2人、歩行・座り・寝るの簡素な状態、感情/会話吹き出し、ランプの小さな揺らぎです。

いま不要なものは、家具や小物の個別PNG化、全8段階背景の完成、座る・寝るのフルアニメ、複雑なライト処理、大量のUIスキンです。家具とアイテムは将来追加できるように、レイヤーと命名だけ準備します。

次の一手は、`assets/visual/backgrounds/inn_room/inn_room_lv01_base.png` のアートターゲットを作り、同時に `scripts/ui/inn_visual_view.gd` 相当の仮表示ノードで、背景・座席・ベッド・入口の座標を確認することです。
